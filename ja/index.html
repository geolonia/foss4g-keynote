Beyond the API
アクセスは解決した。意味はまだだ。

サイロは壊れていない。ライセンスが良くなっただけだ

人はこの手間をプロジェクトごとに一度払う。AIエージェントは、クエリのたびに払わされる。ライセンスはバイトを解放したが、意味は誰も解放していない。

柱 a · 意味論

機械可読であることは、機械解釈可能であることとは違う

  • 同一性——「中央コミュニティセンター」と「中央公民館」は同じ建物か？
  • 意味論——capacity: 設計上の定員か、今そこにいる人数か？
  • 単位・慣習——NGSIv2は緯度・経度。NGSI-LD/GeoJSONは経度・緯度。同じ数字が、正反対の場所を指す。
  • 時間——いつ計測されたか？いつまで有効か？誰が更新したか？

人間は何十年もこの手間を静かに引き受けてきた。AIエージェントはこの曖昧さをそのまま受け継ぎ——「これは変だ」とは決して言わない。

柱 a · 想定される反論

「AIが賢くなれば、勝手に解決するのでは？」

賢いモデルほど、曖昧なデータでの失敗が減るわけではない。より上手く失敗する——間違いがより正しく見え、レビューを生き延びる。

「賢いエージェントほど、意味は要らなくなるのではない。より速く、より多くの意味を、より高い賭け金で消費するのだ。」

柱 b · 賭けた先

私たちはNGSI-LD（ETSI GS CIM 009）という標準に賭けた

  • エンティティ——安定したIDを持つ「もの」。
  • プロパティ——その名前、その定員。
  • リレーションシップ——推測ではなく、エージェントがたどれるリンク。
  • GeoProperty / @context——位置・時間・共有語彙が、標準に組み込まれている。

意味はデータモデルに宿る。各APIの説明書には宿らない。それがこの標準の要点だ。

柱 b · なぜOrion-LDをそのまま使わなかったか

譲れなかった四つの要件

  • フルマネージド・サーバーレス。自治体が自前でブローカーを24時間運用すべきではない。
  • 1エンジンで2プロトコル。NGSIv2（レガシー）とNGSI-LD（将来）を、同じデータの上で。
  • エージェントを一級市民として。ブローカー自体にMCPを、最初のコミットから。
  • セキュリティは内蔵、後付けではない。単一のポリシー層、送信者に紐づくトークン。

これは私たちの要件として述べている——上流プロジェクトへの批判ではない。この四つが、標準をゼロから再実装するという不快な決断を強いた。

柱 b · 正直な代償

払った代償と、得たもの

代償
  • 約3,200件の適合性テストシナリオ。製品コード1行につきテスト1.7行。
  • CIM 009 v1.9.1のサブセット——「準拠」ではない。
  • 上流コミュニティが我々のバグを拾ってはくれない。標準への追随は、恒久的にこちらの仕事になった。
得たもの
  • 自治体がサーバーを運用せずに導入できるサービス。
  • 1エンジン・2プロトコル。
  • 後付けでなく、最初からの一級市民としてのエージェント。
  • 追加サーバーなしのセキュリティ。

「実装は手放せた。標準を手放さなかったから。」· GeonicDBのオープンソース化は予定している——時期は明言しないが、この場で申し上げておく。
